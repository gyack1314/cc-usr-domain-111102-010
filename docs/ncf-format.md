# NCF 嵌套列式文件格式规范

版本：格式版本 1 / 叶编码版本 1
魔数：ASCII `NCF1`（`0x4E 0x43 0x46 0x31`）
本文档是格式的正式说明。实现见 `workbench/ncf.py`，测试见 `tests/test_ncf.py`。

NCF 不兼容任何现有商业系统，面向小型可穿戴合成资料的本地离线存档与投影读取。
资料只作记录，不构成诊断。

## 1. 设计目标与术语

- **行（row）**：顶层 struct 的一条记录。
- **节点（node）**：schema 树中的 struct、list 或叶节点（int64 / boolean / string）。
- **槽位（slot）**：某节点在某一页中的一个实例位置。struct 的槽位由父级结构决定；
  list 元素节点的槽位数等于该页所有非空列表的长度之和。
- **结构流（structure stream）**：描述空值与列表形状的独立编码流，使行边界不依赖
  叶值数量。NCF 使用显式结构流，它与 Parquet 风格的定义级别/重复级别
  （definition/repetition levels）表达能力等价，对应关系见第 8 节。

每个节点按其种类拥有零到三种命名流：

| 节点种类 | validity 流 | lengths 流 | values 流 |
| --- | --- | --- | --- |
| struct（含根） | 仅当 `nullable: true` | 无 | 无 |
| list | 仅当 `nullable: true` | 有 | 无 |
| int64 / boolean / string | 仅当 `nullable: true` | 无 | 有 |

非空节点没有 validity 流：其全部槽位按定义均为非空，省略流本身即表达该约束。

## 2. 整体文件布局

```
+---------------------------------------------------------------+
| magic "NCF1" (4 字节) | format_version: uvarint (当前为 1)      |
+---------------------------------------------------------------+
| 数据页 0 的块序列（前序遍历，块之间无填充）                      |
+---------------------------------------------------------------+
| 数据页 1 ...                                                   |
+---------------------------------------------------------------+
| footer：规范化 UTF-8 JSON（见第 7 节）                          |
+---------------------------------------------------------------+
| u32le footer_len | u32le crc32(footer) | magic "NCF1" (4 字节) |  共 12 字节尾部
+---------------------------------------------------------------+
```

- 所有多字节整数除特别说明外均为**小端字节序**。
- `footer_len` 是无符号 32 位小端整数；页脚因此最大 4 GiB。
- 尾部最后 4 字节必须等于魔数，否则文件不是 NCF。
- 页脚 CRC-32（IEEE 802.3 多项式，与 `zlib.crc32` 一致）覆盖页脚原始 JSON 字节，
  不含长度字段与魔数。
- 零行文件没有任何数据页，数据区为空。

## 3. 分页规则

- 按**顶层行**分页：页目录每项含 `page`（零起始序号）、`row_start`（该页首行的
  全局零起始行号）、`row_count`（本页行数，恒为正）。
- 同一行的全部流必须落在同一页，**行不跨页**。
- 除最后一页外，每页行数等于写入参数 `page_row_limit`；页行范围必须连续覆盖
  `[0, row_count)`。
- 每个页独立持有自己全部节点的流块；投影读取可整页跳过。

## 4. 结构流编码

所有流先序列化为**负载（payload）**，再按第 6 节加帧。负载内整数一律使用
`workbench/domain.py` 定义的无符号 LEB128 uvarint（见第 5.1 节）。

### 4.1 validity 流（定义级别）

负载：

```
uvarint(slot_count) || 位打包的存在位图
```

- 位图按 **LSB-first** 打包：槽位 `i` 位于字节 `i/8` 的位 `i mod 8`，1 表示非空，
  0 表示 null。
- 最后一个字节中不属于任何槽位的填充位必须为 0，读取时校验。
- 位图字节数固定为 `ceil(slot_count / 8)`；`slot_count = 0` 时负载只有长度
  uvarint，位图零字节。

### 4.2 lengths 流（重复级别）

负载：

```
uvarint(defined_count) || uvarint(length_0) || uvarint(length_1) || ...
```

- 流的槽位序列与 list 节点的父级槽位一一对应；null 列表在父 validity 中记 0，
  **不**在 lengths 流中产生条目。
- `defined_count` 等于该页非空列表的个数（空列表也是非空列表，贡献一条长度 0）。
- 每个长度是无符号 64 位 uvarint，允许 0。元素节点流的总槽位数必须等于长度之和，
  读取时强制交叉校验。

### 4.3 values 流

只编码 validity 为 1 的叶值，顺序与槽位顺序一致；null 叶值不产生任何字节。
具体编码见第 5 节。负载不带前导计数以外的额外头：布尔/字符串/整数流的期望条目数
由 validity 位图推出，读取时与目录 `slots` 交叉校验。

## 5. 叶值编码（encoding_version = 1）

### 5.1 整数：uvarint 与 zigzag

无符号整数使用 **LEB128 无符号 64 位**（uvarint）：每字节低 7 位载荷、最高位为
续位标志；最多 10 字节。只接受**最短规范编码**：例如值 0 只允许单字节 `0x00`，
`0x80 0x00` 必须拒绝；解码结果不得达到或超过 `2^64`。截断（续位后无字节）、
超过 10 字节均报错。

有符号 int64 先做 **zigzag** 映射再按 uvarint 编码：

```
zigzag(v) = (v << 1) ^ (v >> 63)      # v ∈ [-2^63, 2^63 - 1]
```

即 0→0、-1→1、1→2、-2→3……写入前对范围做硬性检查，超出 64 位有符号范围直接报错；
读取解码后的值保证落在同一范围。

### 5.2 布尔：位打包

`slot_count` 个布尔按 LSB-first 打包（同 4.1 的位图规则），填充位必须为 0。
字节数 `ceil(slot_count / 8)`。

### 5.3 UTF-8 字符串：长度前缀编码

每个字符串：

```
uvarint(byte_length) || UTF-8 字节
```

- `byte_length` 是 **UTF-8 字节数**，不是码点数。
- 空字符串编码为单个 `0x00`，与 null（在 validity 中为 0、无负载条目）严格区分。
- 写入时 Python `str` 先编码为 UTF-8；含未配对代理项的字符串无法编码，写入前报错。
- 读取时按字节长度切片后用严格 UTF-8 解码，任何非法序列（含非法续字节、过长编码、
  代理码点、超范围码点）都产生可定位 `FormatError`，绝不静默替换。
- 单条字符串最大字节数受 uvarint 64 位范围约束，实际文件受页脚 32 位长度间接约束。

## 6. 块帧与每页校验

每个流块在数据区中的帧格式：

```
uvarint(payload_len) || payload (payload_len 字节) || u32le crc32(payload)
```

- 读取时先按目录定位（见第 7 节），解码 `payload_len`，其值必须与
  `block.length - 帧头字节数 - 4` 完全相等，否则报“块帧长度与目录不符”。
- 校验和只覆盖 payload；CRC 不匹配报“块校验失败”，错误带页号、列路径、流名与
  绝对偏移。
- payload 内任何 uvarint 截断/非规范、位图填充位非零、字符串非法 UTF-8、条数与
  目录/结构流不一致，都在该块的定位信息下报错。
- 因此**每页的每个流块都带独立校验**；全量 validate 解码全部块，投影只校验它实际
  读取的块。

## 7. 页脚（自描述目录）

页脚是 `workbench.io.canonical` 产生的规范化 JSON（`ensure_ascii=False`、
键排序、无空白、拒绝 NaN/Infinity），UTF-8 编码，字段：

| 字段 | 含义 |
| --- | --- |
| `format` | 固定字符串 `"ncf"` |
| `version` | 文件布局格式版本，当前 1 |
| `encoding_version` | 叶编码版本，当前 1 |
| `row_count` | 顶层行数（非负整数） |
| `page_row_limit` | 写入时的每页行数上限 |
| `schema` | 完整 schema 树（含每个节点的 name/kind/nullable、struct fields、list element） |
| `leaf_columns` | 全部叶列的点路径，顺序与 schema 前序遍历一致 |
| `pages` | 页目录，每项含 `page`、`row_start`、`row_count`、`blocks` |

每个 block 项：`path`（点路径，根节点为空字符串；list 元素固定路径段 `item`）、
`stream`（`validity` / `lengths` / `values`）、`offset`（块帧相对文件起点的绝对
字节偏移）、`length`（整个块帧的字节数）、`slots`（该流在本页的槽位/条目数）。

打开文件时对页脚做如下结构性校验，任何失败都产生带定位的 `FormatError`：

1. 头尾魔数、格式版本与编码版本（不支持的版本直接拒绝）；
2. 页脚长度范围与 CRC；JSON 必须为合法 UTF-8 且无重复键；
3. schema 自身合法（兄弟字段名唯一且不含点、element.name 固定 `item`、
   kind 仅取规定值、nullable 为布尔）；
4. `leaf_columns` 与 schema 推导出的叶路径集合完全一致且无重复；
5. 各页 `row_start` 从 0 连续、`row_count` 为正、行数之和等于 `row_count`；
6. 每个块偏移落在数据区内（头部之后、页脚之前）、块之间互不重叠；
7. 每个块的 `(path, stream)` 都属于 schema 允许的流集合，页内无重复结构流，
   且每页恰好包含 schema 要求的全部流；
8. 零行文件不得包含数据页。

## 8. 结构流与定义级别/重复级别的等价关系

显式结构流是 D/R 级别的逐节点分解，五种约定形态的区分方式：

| 形态 | validity（定义级别） | lengths（重复级别） | 子节点流 |
| --- | --- | --- | --- |
| null struct | 该槽位为 0 | — | 子流对应槽位必须为空 |
| 空 struct `{}` | 该槽位为 1 | — | 子字段按自身 schema 展开（缺失可空项为 null） |
| null 列表 | 列表槽位为 0 | 无条目 | 元素流无对应槽位 |
| 空列表 `[]` | 列表槽位为 1 | 一条长度 0 | 元素流无槽位 |
| 含 null 元素的列表 | 列表槽位为 1 | 一条长度 N | 元素 validity 对应位置为 0 |

嵌套列表（list of list）每层各自持有 validity + lengths，因此
`null 列表 / [] / [null] / [[]] / [[null]]` 五种形态编码互不相同，可逐行往返恢复，
不需要从叶值数量反推行边界。这满足“使用明确的定义级别与重复级别或等价可说明的
结构流”的要求：validity 即定义级别信息，lengths 即重复级别信息，且以每节点独立
流的形式显式存放。

## 9. 读取模型与投影

### 9.1 read_at 源

读取端只依赖一个可注入源对象，协议为：

```python
source.size          # int，文件总字节数
source.read_at(offset, length) -> bytes   # 必须精确返回 [offset, offset+length)
```

- 越界、负参数、返回长度不足都视为读取错误并包装成带偏移的 `FormatError`。
- 每次调用的 `(offset, length)` 由源自行记录（`BytesSource` / `FileSource` 内置
  `reads` 列表），用于观察实际读取范围与字节数。
- 打开文件固定产生三次读取：头部 5 字节、尾部 12 字节、页脚；之后每个被访问的
  块帧恰好一次读取（进程内带缓存，重复投影不重复 I/O）。

### 9.2 全量读取与 validate

- 全量读取解码所有结构流与 values 流，重建完整嵌套行；输出等价于写入前的
  规范化结果（缺失可空字段已补成 null）。
- `validate()` 读取并交叉校验**所有页的所有块**（CRC、槽位数、长度和、空 struct
  子节点为空、位图填充、UTF-8、uvarint 规范性），任何错误都失败；成功返回行数、
  页数与叶列清单。

### 9.3 投影读取

- 投影参数为叶列点路径列表。读取器先在页脚中计算每个所选叶列的全部祖先路径，
  只打开这些路径上的流块；未选叶列的 values 块**一次都不会被读取**。
- 列表形状由祖先 list 的 lengths 流、空值由 validity 流重建；未选 struct 字段在
  输出对象中直接缺键，但所选子树的 null/空列表/null 元素位置与全量读取完全一致。
- 投影成功只代表被访问的块有效，**不得据此声称整文件有效**；未访问块的损坏不会
  被发现，需要有效性结论时必须调用 `validate()`。

### 9.4 行范围选择

`read(columns, row_start, row_end)` 选择半开区间 `[row_start, row_end)`：

- 完全落在区间外的页整页跳过，不产生任何块读取；
- 不允许先解码整行 JSON 再删字段——NCF 没有 JSON 行概念，解码本身按列流进行；
- 非法范围（负起点、起点大于终点、超出总行数）在任何块读取之前报错。

## 10. 写入前校验与规范化

写入端在产生任何字节之前完成校验，错误输入不会留下半成品文件：

1. schema 校验同第 7 节第 3 条；
2. 每行递归校验：Python 类型必须与 kind 精确匹配（`bool` 不被当作 `int`）；
3. struct 的未知字段报错；缺失字段在必选时报错、可空时规范成 null；
   `{}` 仅当其全部子字段可空时合法，并展开为全 null 子项；
4. list 元素逐个校验，元素本身可空时 null 与 `{}` 分别保留；
5. int64 范围、布尔类型、字符串可 UTF-8 编码性在写入前检查（见第 5 节）。

文件通过同目录临时文件 + `os.replace` 原子落盘并 fsync。

## 11. 错误定位约定

所有格式错误为 `workbench.ncf.FormatError`（`ValueError` 子类），消息附带可用的
定位字段：`page`（页号）、`path`（列点路径，根为 `<root>`）、`stream`
（validity/lengths/values/footer/header）、`offset`（绝对字节偏移）。典型场景：

- 读取越界 → 带请求偏移的“读取越界”；
- 重复列/重复结构流 → 页号与流标识；
- 结构层级非法（元素路径不是 `item`、长度和与元素槽位不符、空 struct 子节点非空）
  → 节点路径与页号；
- 不支持的版本 → 版本字段所在偏移；
- 截断/非规范 uvarint、非法 UTF-8、位图填充位非零 → 块定位加流内偏移。

## 12. 限制与保留事项

- 单文件页脚最大 4 GiB（尾部长度字段为 u32）；数据块偏移同为 64 位寻址空间内的
  文件偏移，实际受本地文件系统限制。
- 叶类型仅限 int64、boolean、UTF-8 string；未知 kind 在写 schema 时即拒绝。
- 版本号是硬性门禁：高版本文件必须在版本检查处明确失败，不尝试猜测兼容。
- 格式不保存业务语义与诊断结论，只保存记录与结构。
